VRR (Variable Refresh Rate)

Author: Andrilaz | Max.Mov • Special thanks: ProTos1080p

ℹ️ Reference

VRR (G-Sync / G-Sync Compatible, AMD FreeSync, VESA Adaptive-Sync, HDMI 2.1 VRR) — Technology that synchronizes monitor refresh rate dynamically with in-game frame rates. Designed to eliminate V-Sync drawbacks while providing tear-free, fluid visuals with minimal display delay within its operating range. It is not a silver bullet if game engine stutter issues exist.

Why VRR does not replace V-Sync: Video Explanation

V-Sync (Vertical Synchronization) — Driver setting (NVCP / NVAPP) or in-game toggle. Simply put: V-Sync forces system pipelines to wait until display scanout completes the current frame. V-Sync remains necessary alongside VRR to eliminate frame time variance tearing completely.

NVCP / NVAPP — NVIDIA Control Panel or the new NVIDIA App application.

Low Latency Mode — Driver-level setting in NVIDIA Control Panel (Low Latency Mode / LLM). When set to "Ultra", it is referred to as ULLM/NULL (NVIDIA Ultra Low Latency Mode), referencing zero frame queueing.

🟢 VRR on NVIDIA

  1. Enable VRR (G-Sync / G-Sync Compatible, AMD FreeSync, VESA Adaptive-Sync, HDMI 2.1 VRR) on your monitor via its OSD menu.
  2. Enable VRR in drivers:
    • NVIDIA App (NVAPP): Navigate to System -> G-SYNC & Surround -> Enable G-SYNC for FULL SCREEN MODE ONLY. Under Display Properties, check "Enable settings for the selected display model".
    • NVIDIA Control Panel (NVCP): Navigate to Set up G-SYNC -> Enable G-SYNC -> Choose FULL SCREEN MODE ONLY. Below, select your display and check Enable settings for the selected display model.
  3. In games WITH Reflex Support: V-Sync ON (In-Game) + Reflex ON. (When working correctly, maximum FPS drops slightly below display refresh rate automatically).
  4. In games WITHOUT Reflex Support: V-Sync ON (In-Game / or force via NVCP/NVAPP if in-game implementation is poor) + Low Latency Mode: Ultra* (Driver) OR inject Reflex via RTSS/SpecialK with a fast frame rate cap using formula: Refresh - (Refresh x Refresh / 3600) = FPS Cap**.

🔴 VRR on AMD

  1. Enable VRR (G-Sync / G-Sync Compatible, AMD FreeSync, VESA Adaptive-Sync, HDMI 2.1 VRR) on your monitor via its OSD menu.
  2. In Radeon Software -> Display section -> Enable VRR / FreeSync.
  3. In games WITH AMD Anti-Lag 2 Support: V-Sync ON (In-Game) + AMD Anti-Lag 2 ON (In-Game) + Cap frame rate using formula Refresh - (Refresh x Refresh / 3600) = FPS Cap**.
  4. In games WITHOUT AMD Anti-Lag 2 Support: V-Sync ON (In-Game / Adrenalin) + AMD Anti-Lag ON (Driver)* + Cap frame rate using formula Refresh - (Refresh x Refresh / 3600) = FPS Cap**.

⭐ Important Clarifications & Details

  • * If you encounter unexpected performance drops or instability with Low Latency Mode: Ultra or Anti-Lag enabled, set the toggle back to Default. Ultra mode can sometimes exhibit compatibility issues with specific DirectX 12 engines.
  • ** This dynamic Reflex limit formula ensures frame times remain safely within the active VRR window, avoiding limiter jitter. Setting exact caps via this equation is optional, as long as caps remain below the calculated value.

⚠️ Important:

  1. Never set V-Sync, Low Latency Mode, or FPS Limiter options inside the GLOBAL driver profile (NVCP/NVAPP). Configure settings on a per-game basis when necessary.
  2. Configure the Overdrive (pixel response acceleration) setting in your monitor OSD. Usually a Medium setting provides optimal performance without excessive inverse ghosting.
  3. Avoid using the Discord overlay as it breaks VRR. Always audit active overlays.
  4. Enabling the G-Sync status indicator overlay inside display drivers breaks VRR.
  5. Never enable "Dynamic Refresh Rate" under Windows Advanced Display Settings.

🔵 Optional: Disabling Windows VRR

If you experience unusual VRR issues, try disabling this system toggle:

Path: Settings -> System -> Display -> Graphics -> Default Graphics Settings -> Variable Refresh Rate -> OFF.

Disabling this will not impact VRR functionality across modern titles on Windows 11. However, disabling this setting prevents VRR from functioning when unfocused window overlays sit on top of game windows. Keep it enabled unless specific problems arise.

🚫 Without VRR

If your monitor has an extremely narrow VRR range (e.g., 48-75 Hz), VRR may not be worth utilizing. Test performance carefully on your setup.

Additional Information

1. Requirements for Correct VRR + V-Sync Functionality

For VRR to operate as intended, games require Independent Flip presentation (Read detailed article), V-Sync (SyncInterval=1/AllowTearing off) to absorb frame time variance, and an FPS limiter below maximum display refresh rate to stay inside the VRR window. All VRR implementations rely on dynamic VBLANK intervals.

In modern games (DX11+ / Reflex enabled), in-game V-Sync toggles usually function properly without forcing driver-level options. In-game settings are aware of engine states: Ingame VSync > NVAPP VSync.

Driver-level V-Sync controls frame presentation timing exclusively. In-game V-Sync toggles often manage broader internal engine variables—ranging from built-in frame limiters to per-frame asset streaming rates.

2. Frame Limiters (Without Native Reflex)

In-game frame limiters CAN offer lower latency when implemented directly before simulation/input polling loops.

If an in-game limiter is erratic or missing, rely on fast limiters like RTSS Async/back edge sync/Reflex mode or SpecialK low-latency limiters.

Driver-level limiters (NVCP/NVAPP) have drawbacks—they are less flexible, rely on NvAPI_D3D_Sleep placement in Reflex titles, and cannot be changed on the fly.

3. VRR Flicker on VA / OLED Panels
Minor brightness flickering is normal on VA and OLED panels during heavy frame time variance.

Verify G-SYNC is set to Fullscreen mode only, verify VRR settings, and try disabling Windows VRR.

4. DLSS Frame Generation with VRR + V-Sync
NVIDIA Frame Generation fully supports VRR + V-Sync (added in Driver 526.98).

Some titles gray out in-game V-Sync when Frame Gen is enabled; force V-Sync via GPU drivers (NVCP/NVAPP) in these cases.

5. Reflex & Low Latency Mode Details

The CPU, GPU, and display operate as three asynchronous execution stages. Latency builds up primarily when the CPU queues frames ahead of GPU rendering.

NVIDIA Reflex synchronizes CPU execution with GPU execution, issuing input sampling and simulation commands right before GPU frame render completion. Eliminating queueing drastically reduces delay under GPU-bound scenarios.

6. Reflex + Boost Mode Explained
Boost mode disables GPU frequency downclocking (similar to "Prefer Maximum Performance") and optionally enables aggressive marker timing optimizations (bUseMarkersToOptimize).

7. Counter-Strike 2 Reflex Implementation
NVIDIA Reflex in CS2 provides measurable latency gains over non-Reflex or ULLM modes, despite community rumors regarding `-noreflex` switches.

8. Hardware G-Sync Module Monitors
G-Sync module displays feature hardware Variable Overdrive and module-level LFC processing.

9. Why Avoid Windowed G-SYNC Modes?
Windowed G-SYNC was designed during Windows 7/8 when windowed apps routed through legacy DWM composition. Modern borderless windows run under Independent Flip and act as full-screen surfaces, making Windowed G-SYNC redundant and prone to unwanted desktop flickering.
